F1 — Required — BOT-1 adjudicated VALID; discovery AND placement of the envelope are not
  block-scoped. (runtime/scripts/inventory.py `find_signature`, `_place_signature`)
  Motivating line (code): "for idx, line in enumerate(lines): m = SIGNATURE_LINE.match(line)"
  — every line of the document, not the [(start,end)] ranges find_blocks returns; and
  `_place_signature`: "idx, _env = find_signature(lines); if idx is not None: lines[idx] = line".
  Motivating line (spec, DB1): "written as a detached envelope block that
  find_blocks/parse_entries TOLERATE" — the envelope belongs INSIDE the block the parsers read;
  the code's own docstring claims "so it sits where find_blocks already looks".
  Reproduced in scratch (probe P1/P2/P2b/P3) with an indented prose example of the format
  placed ABOVE the inventory heading — the exact line docs/reports/u-sig-2/build.md:15 commits:
   P1 unsigned block + prose example, `check --pubkey`: exit 1, but the diagnostic is
      "signature record binds inventory digest 0000…, but the entries present digest to
      776617d2… — an entry was added, dropped or changed after signing" — the truthful
      message is UNSIGNED. Wrong diagnosis, right verdict.
   P2 `sign` on that doc: exit 0 and the PROSE line 5 is overwritten with the real envelope;
      the block itself stays unsigned.
   P2b/P3 `check --pubkey` then PASSES with the envelope outside every block (an envelope
      moved from the block into the preamble still verifies).
  Integrity assessment (agree with the integrator's downgrade P1->P2): no acceptance path
  opens — the digest is re-derived from the union of all blocks' entries, so a moved or pasted
  envelope can only verify if the coordinator's key signed exactly this set. It is a
  false-refusal / mis-placement robustness defect, but a run report that quotes the format is
  one paste away and the run-close gate (run_report.signed_inventory reads the whole report
  text) inherits it. Fix is in-unit and small: iterate only find_blocks ranges in
  find_signature; in _place_signature replace only an envelope inside a block, else append to
  the first block; add the prose-example test (unsigned -> "UNSIGNED"; signed -> verifies).
  Severity Required because DB1's contract is an envelope the BLOCK carries, and because the
  committed build.md already contains the trigger line — but it does not block the batch if the
  batch owner prefers to land it as the first follow-up commit; either way the thread on PR #490
  comment 4057859153 needs an in-thread answer naming the commit.

  today: presence only) — and proves the receipt covers these bytes".
