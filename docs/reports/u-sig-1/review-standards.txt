1.1 Per spec DESIRED BEHAVIOUR item 1 — verify.py verdict object + signed envelope
  Motivating line: "verify.py builds a machine-readable VERDICT OBJECT (manifest path,
  the full argument tuple, fatal/notes lists, exit code, toolchain, UTC timestamp)"
  EXPECT (standards):
   a. The record is built by ONE function that is the single source of truth for the
      field set; dispatch-sign.py must import or share that field list, never
      re-type it (Fowler: Duplicated Code / Shotgun Surgery if a field is added).
   b. Signing key seed is read from a path given on argv (`--transcript-seed` or
      similar, modelled on --dispatch-pubkey), opened with 0600 expectation, NEVER
      embedded, NEVER passed via a shell string. Any subprocess call uses a list
      argv — no f-string into shell=True.
   c. Envelope write is atomic-ish (write temp, rename) or at minimum fails closed:
      if signing fails, verify.py exits non-zero rather than emitting an unsigned
      artifact and exit 0.
   d. The no-flag path is byte-identical: the build of the verdict object must not
      add stdout lines or change exit codes when no flag is passed.
   e. Timestamp is UTC ISO-8601 with explicit "Z"/"+00:00" — no naive datetime.now().

1.3 Per spec item 3 — run_report.py verifier-ran leg
  Motivating line: "with a committed pubkey present it REQUIRES the signed
  transcript (the ledger entry alone no longer suffices), with the unsigned path
  preserved when no pubkey exists."
  EXPECT:
   a. FAIL-CLOSED ordering: presence-of-pubkey decides the lane BEFORE the ledger is
      consulted; a malformed/undecodable envelope is a FAIL, not a fall-through to
      the unsigned lane (that would be Fowler "Speculative Generality" turned into

      is exactly BOT-2. My blind expectation: the key should be read at the grading

      implementation reads it at `inventory_at`, that is a standards defect
      (fail-open) independent of the bot's finding.
   c. Signed fields bound to report claims: manifest path, manifest sha, exit code,

      execute_nc, lighting). This is BOT-1. Blind expectation: at minimum the
      signed_transcript() checker should refuse a transcript whose args say
      report-only/planning for a mutation-mission manifest. If args are signed but
      never read, that is Fowler "Dead Code"/"Speculative Generality" — signing a
      field nobody checks.
   d. base64 decode and JSON parse of the envelope wrapped in try/except that
      RETURNS a failure reason string, not a bare exception that crashes grading
      (neighbours in run_report.py return (ok, reason) tuples).
