C-1 (Critical) — classify() trusts a worker-planted SYMLINK whose target is root-owned:
    sound-lane FALSE GREEN.
    verify.py:758-759 resolves the path and :770 probes ONLY the resolved parent. The PATH
    entry's own directory — the thing the worker writes the link into and can re-point at any
    moment — is never probed. Repro (rv.py test_R1_symlink_to_interpreter): worker-writable
    drop/ first on PATH, `drop/gh -> /bin/sh`; a committed file `api` at the repo root (cwd of
    the verifier) that prints a forged APPROVED at `$(git rev-parse HEAD)` by carol.
    `classify(drop/gh -> /bin/sh) -> system`. Sound lane, --provenance ci, git from /usr/bin:
      rc= 0   verify: OK — all required checks passed
      SH-API ARGV: --paginate repos/o/r/pulls/7/reviews
      SH-API ARGV: repos/o/r/pulls/7
    No FAIL, no NOTE; the sound lane consulted the worker's script twice (reviews + author).
    /bin/sh is the cleanest key (argv `api …` is a relative script path resolved against cwd =
    the graded repo) but any system interpreter or `/usr/bin/env` (which re-resolves `api` on
    the same PATH) works. This is precisely the frozen bar's "something the graded worker could
    have replaced or REDIRECTED".
    Fix shape: probe the UNRESOLVED entry too — `os.access(Path(path).parent, W_OK)` → worker-
    writable — and walk every symlink hop (os.readlink loop or Path.resolve per component),
    classing worker-writable if ANY hop's directory is writable/owned. Add the regression test
    (symlink in a writable dir → system-owned target must class worker-writable) and revert-
    prove it; the existing N2a test (:4241) covers only the inverse direction.

C-2 (Critical) — W_OK is a MODE probe; a worker-OWNED 0555 dir classes "system":
    sound-lane FALSE GREEN.
    verify.py:770 `os.access(p.parent, os.W_OK)` is false for a directory the effective user
    OWNS with mode 0555 — a mode the owner sets and can unset (`chmod u+w`) at will. Repro
    (rv.py test_R1_owner_0555): worker mkdtemp's ~/rv-drop-…, writes the stub gh, chmods file
    and dir 0555, puts it first on PATH. `owner==euid: True | mode: 0o555`. Sound lane,
    --provenance ci, git from /usr/bin:
      rc= 0   verify: OK — all required checks passed
      planted gh CONSULTED?: True
    Also confirmed at the classify() level for a 0555 dir under /var/folders/…/T and under
    $HOME in the gate-shaped child (no TMPDIR, cwd=repo): "system" both times. The builder's
    report says "any dir/file this user can write → worker-writable"; a dir the user owns is a
    dir the user can write, one chmod away.
    Fix shape: class worker-writable when `st_uid == os.geteuid()` (or euid is in the
    owning group with g+w) for the resolved file, its parent, and every hop's parent — an
    ownership probe alongside the mode probe. Regression test + revert-proof. NOTE this will
    (correctly) class the 0555 gate fixture worker-writable — see R-1.

R-1 (Required) — the 0555 sysbin fixture (test_verify_gate.py:41-64) is host-dependent and
    encodes C-2 as the happy path.
    (i) RED on a Linux temp layout: reproduced with TMPDIR=/tmp — mkdtemp lands under the
    child's gettempdir() and classify():768 classes it worker-writable; expect the 7 gate tests
    the builder listed to FAIL on the ubuntu `tests (1..3)` jobs (CI on #493 was still PENDING
    at review time; not exercised on a runner). (ii) Owned by euid + 0555 is exactly C-2; a
    correct ownership probe makes this fixture fail, so the fixture cannot survive the fix it
    accompanies. (iii) Leaks: rmtree(ignore_errors=True) cannot empty a 0555 dir — 3
    `vgate-sysbin-*` dirs leaked on this host; hard-link count on the real Cellar gh/gitleaks
    is 4. (iv) `os.chmod(dst, 0o555)` on a hard link rewrites the HOST binary's mode.
    Fix shape: the gate tests need a git/gh the effective user neither owns nor can write.
    Options: (a) a coordinator-declared trusted authority dir (the design question the builder
    raised — needs a ruling), (b) run the gate lanes with PATH restricted to genuinely root-
    owned dirs when the host has them (/usr/bin on macOS carries the xcode git shim; skip the
    sound-lane gate tests with a named reason when it does not), (c) in CI, install the tools
    where root owns them. Whatever is chosen: copy, never hard-link; chmod the dir back to 0755
    before rmtree in the atexit hook.

R-2 (Required) — the `os.getcwd()` root (verify.py:762) makes EVERYTHING worker-writable when
    the verifier's cwd is `/` (r="/" is a parent of every path) — fail-closed but a sound lane

    a message that blames the binary. Cosmetic in security terms, operational in practice.
    Either skip the cwd root when it is `/` (or any dir the user cannot write), or word the
    fatal to name the root that matched.
