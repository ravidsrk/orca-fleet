N-1 (Nit) — `classify()` feeds `_nodes()` `os.path.abspath(path)` (verify.py:805), and abspath
    collapses `..` LEXICALLY, so the walk probes the lexically-normalised path, not the path the
    kernel would exec when a `..` follows a symlink. Re-derived: `/tmp/../etc/hosts` → abspath
    /etc/hosts (walk: /, /etc, /private, /private/etc, /private/etc/hosts) vs kernel
    /private/tmp/../etc/hosts (which also passes /private/tmp). I could NOT turn this into a false
    "system": the lexical path always retains the directory that holds any worker-planted link (so
    ownership catches it), `Path.resolve(strict=True)` at :806 fails closed whenever the lexical
    and kernel paths name different existing/non-existing files (`/tmp/../usr/bin/git` →
    worker-writable), and the only root-owned symlinks on macOS/ubuntu (/tmp /var /etc → /private;
    /bin /lib /sbin → /usr) alias parallel trees. The walk's last node equalled `resolve()` on
    every path I tried. It is still a soundness argument that rests on the host's link layout
    rather than on the code. Cheap hardening: pass `os.path.join(os.getcwd(), path)` (un-
    normalised) to `_nodes`, and/or return worker-writable when `nodes[-1][0] != p`.

N-2 (Nit) — `test_c2_a_worker_owned_0555_file_in_a_root_owned_dir_is_worker_writable`
    (tests/test_verify.py:4429) overclaims in its name: the file sits in $HOME/orca-h409-r4-*/,
    not in a root-owned dir (a euid-owned file in a root-owned dir cannot be built without root).
    It is a correct PREDICATE test of `_worker_controls` on the file's own lstat and is the one
    round-4 test that ERRORs rather than FAILs on revert (interface-only, as the builder said).
    Rename to say what it proves (…_file_alone_satisfies_the_ownership_probe).

N-3 (Nit) — On a macOS host the admitted sound-lane PATH carries git only: no gh, no gitleaks
    live under /usr/bin here, so the 10 sound-lane GATE tests now exercise custody "absent" for
