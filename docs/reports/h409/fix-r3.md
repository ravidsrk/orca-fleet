## R1 (P0) — classify() trusted a worker-writable `SYSTEM_BINS` dir by NAME

### Reproduction on HEAD-before-fix (bb2996b8 / adb8316a verifier)

Stub `gh` planted in `/opt/homebrew/sbin` (user-writable here: `drwxrwxr-x ravindra`), first on a
PATH that otherwise carries only git; `--repo o/r` pinned, `--provenance ci`, real executable revert
control. The probe was created and removed inside the run; the real gh in `/opt/homebrew/bin` was
never touched.

```
which gh (crafted PATH) -> /opt/homebrew/sbin/gh
== SOUND lane (--provenance ci), worker-planted gh in /opt/homebrew/sbin
rc= 0
OUT: … NOTE: negative control EXECUTED — … (RED, as required)
     verify: OK — all required checks passed
stub gh CONSULTED?: True
classify(symlink in listed dir) -> system        (N2a)
classify(plain file in listed dir) -> system     (N2b)
classify(/usr/bin/gh) -> system
```

Exit 0 on a sound lane over a review the worker wrote — reattack.md §R1 verbatim.

### Root cause

`_Authority.classify()` returned `"system"` when `str(Path(path).parent) in SYSTEM_BINS`, BEFORE
resolving the symlink or probing `os.access(…, W_OK)`. The list carried `/opt/homebrew/bin` and
`/opt/homebrew/sbin`, which Homebrew leaves owned by the login user.

### Fix

`SYSTEM_BINS` is gone. `classify()` always resolves the path (symlinks followed) and always probes:
under the temp dir, the cwd, either toplevel, or any dir/file this user can write → `worker-writable`;
otherwise `system`. A root-owned `/usr/bin` still classes system because the effective user cannot
write it. (Consequence on a Homebrew host, by the frozen ruling: `/opt/homebrew/bin/{gh,git}` are
worker-writable → advisory on the native lane, fatal on sound lanes. That IS the acceptance bar.
Note for the record: a verifier running as root sees every dir writable and classes everything
worker-writable — fail-closed, and sound lanes are not meant to run as the worker anyway.)

### Reproduction after the fix

```
== SOUND lane (--provenance ci), worker-planted gh in /opt/homebrew/sbin
rc= 2
ERR: FAIL: review_authority: gh at /opt/homebrew/sbin/gh is worker-writable — a lane claiming
     soundness (provenance=ci) cannot take its independent review from a binary the graded worker
     could have replaced; fail-closed (h409 F-1)
     (plus the R2 fatal for the temp-dir git the harness puts on PATH)
stub gh CONSULTED?: False
classify(symlink in listed dir) -> worker-writable   (N2a)
classify(plain file in listed dir) -> worker-writable (N2b)
classify(/usr/bin/gh) -> system
```

(`create=True`: the pre-fix verifier trusts it, the fixed one has no such attribute to consult).

## R2 — git and gitleaks were not pinned; post-control legs re-resolved `git` on PATH

### Reproduction on HEAD-before-fix

Empty user-writable `drop/` first on PATH; the committed `check.py` (run by the executed control)
writes a logging `git` stub there, then asserts the criterion.

```
== NATIVE lane, control plants git into …/drop
rc= 2
ERR: FAIL: --execute-nc: could not create the clean worktree at head_sha:
planted git?: True | CONSULTED post-control?: True
PLANTED-GIT ARGV: -C …/tmp1zn_uduy worktree remove --force …/orca-nc-p1potvkq/wt
PLANTED-GIT ARGV: -C …/tmp1zn_uduy worktree add --detach …/orca-nc-esxm5b47/wt d40aa546…
PLANTED-GIT ARGV: -C …/tmp1zn_uduy worktree remove --force …/orca-nc-esxm5b47/wt
```

The worktree teardown, the clean-head re-run's `worktree add`, and every later `_git` leg ran the
binary the control had just planted. (With a stub that `exit 1`s the run only breaks; a stub that
forwards to the real git and lies about one tree is the false-GREEN shape.)

### Fix

`_Authority.pin_git()` runs FIRST in `resolve()` (classify() reads the toplevel through git, so the
path lands before the class), storing the absolute path and its custody; `git_bin()` hands it to
every git leg — `_git`, `_git_bytes`, `_evidence_toplevel`, `_root_arg`, the NC worktree
add/checkout/diff/revert/apply/status/remove, `_Transcript.build`'s `git --version`. No `"git"`
argv head remains. A library caller pins on first use (before its control, as `verify()` ensures)
and never again; an absent git is a pinned state (`_run`/`_run_bytes`/`_run_at` refuse `argv[0] is
None` with `ABSENT_GIT` rather than looking on PATH). `authority_leg()` runs first in `verify()` for
EVERY unit class: worker-writable git → fatal on a sound lane, `NOTE: authority: advisory (git at …)`
on the native lane. `gitleaks` is pinned and classed the same way and always invoked by its pinned
absolute path; because it can only ADD a hit above the built-in floor (a replaced one yields at
worst a fatal, never a false GREEN) a worker-writable one is still consulted and its custody is
NOTEd on every lane — this is a judgment call inside the spec's "where used" clause, taken so the
CI `$RUNNER_TEMP/gitleaks` leg keeps exercising the scanner path.

```
== SOUND lane, git first on PATH is in a worker-writable dir at startup

ERR: FAIL: authority: git at …/drop/git is worker-writable — a lane claiming soundness

     worker could have replaced; fail-closed (h409 R2)
```

## R3 — the pinned gh ran under the un-scrubbed ambient environment

### Reproduction on HEAD-before-fix

A gh wrapper that logs the NAMES of its env vars (values deliberately not logged: this host's
ambient env carries real tokens), with `GH_HOST=attacker.example GH_CONFIG_DIR=/evil` set:

```
gh saw env:  PATH HOME GH_CONFIG_DIR GH_HOST GITHUB_PAT_CLASSIC GITHUB_TOKEN GH_TOKEN
```

The forged host AND every ambient secret reached the subprocess.

### Fix

All GitHub reads go through one seam, `_Authority.api()`: the pinned gh, `env=_Authority.gh_env()` —
the allowlist `PATH, HOME, TMPDIR, TMP, TEMP, GH_TOKEN, GITHUB_TOKEN`, each only when present.
`GH_HOST`, `GH_CONFIG_DIR`, `GH_REPO`, `SSL_CERT_FILE`, `HTTPS_PROXY` and everything else never pass.
The coordinator opts a host in explicitly by pinning `--repo host/owner/name`
(`_Authority.split_repo`), which becomes `gh api --hostname host repos/owner/name/…` — no new flag,
so the signed transcript argument tuple and run_report's `SIGNED_ARGS` are untouched.

