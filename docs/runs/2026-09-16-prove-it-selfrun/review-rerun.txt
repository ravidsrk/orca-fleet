  Four behaviours, each a real assertion against check_oracle_scope's return:
    1. Dict-bogus: oracle_scope is a dict whose kind is not characterization and not
       documentation. The function MUST refuse AT the kind gate — return list equal to
       (or containing as the sole/first element) the kind-gate message
       "oracle scope: kind must be characterization or documentation" — and MUST NOT
       fall through to a later gate's message.
    2. Non-dict disjunct: oracle_scope is present but not a dict (list / str / int / bool;

       be the kind-gate message. Empty list is acceptable if the fixture is otherwise
       complete; a later-gate error is also acceptable if it proves the kind check was
       passed. The assertion has to be about the kind gate, not about the whole function
       succeeding for unrelated reasons.
    4. Legal kind "documentation": the other legal kind, same "past the kind gate" claim.

    crashed if the kind gate admits.

    characterization allowed).
