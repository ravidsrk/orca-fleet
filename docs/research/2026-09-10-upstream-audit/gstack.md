## 4. Mechanisms — what each does, what orca-fleet has, what adopting would take

### 4.1 `gstack-evidence` (verification-evidence ledger)
**What it does.** `run --label L -- cmd` is a transparent wrapper: child stdout/stderr stream through, exit code always passes through ("must never turn green tests red", `:15-18`), a 0600 log (2 MB cap, 30-day prune) is written, and one JSONL record appends `{ts,label,command,cmd_sha256,exit,duration_s,commit,tree,dirty,wtree,log_path,redacted}`. Bun-autoloaded `.env` vars are scrubbed from the child by value equality so the ledger certifies a run CI would perform (`:201-248`; unreadable `.env` fails open). `check --label L --expect-cmd '<exact string>' --max-age H --allow-paths a,b` grades each label FRESH (recorded exit 0, `cmd_sha256` matches the exact string, current `gstack-wtree` equals the recorded `wtree` modulo allow-listed paths, within max-age) / STALE / MISSING; any git failure degrades to STALE, never throws (`:31-35`). Machine-local by design (`:27-30`). In `/ship` Step 16 and `/land-and-deploy` 3.5b the check is **advisory**: "a failed CHECK never blocks; a failed RUN does" (`ship/SKILL.md:947`, `readiness-gate.md:122`).
**orca-fleet today.** Doctrine: `evidence-manifest.md:31-33` (`commands[]` with exit + artifact path), `:96` ("Never a summary"), `release.md:26-27` (fresh-evidence rule in prose). Mechanism: none — no runner records a command; `verify.py` reads the manifest's `commands[]` but binds nothing to a tree; the clean-env re-run is coordinator-run (`evidence-manifest.md:117`).
**Adopting.** (a) `runtime/scripts/evidence-run.py` (stdlib): wrapper that appends the same record shape into the unit's manifest `commands[]` (`cmd`, `cmd_sha256`, `exit`, `artifact`, `wtree`, `commit`); (b) `runtime/scripts/wtree.sh` ported verbatim (62 lines, bash, MIT); (c) `verify.py check_commands`: for a mutation unit require ≥1 recorded command with exit 0 whose `wtree` equals `git rev-parse <head_sha>^{tree}` (committed content) — this turns "tests pass at that exact SHA" from a coordinator-only step into a machine check on the recorded run. Keep it **fail-closed** (a STALE record fails the unit; the coordinator's clean-env re-run remains). Effort: ~1 day; the dotenv scrub is unnecessary because orca-fleet workers run in fresh worktrees under Orca, not bun.

### 4.2 `gstack-wtree` (content fingerprint)
**What it does.** Copies the real index to a temp index (preserving the stat cache), `git add -A`, `git write-tree`; prints a tree hash that survives commit/rebase/amend of identical content and changes on any untracked non-ignored source file (`:9-14`). ~0.09 s warm.
**orca-fleet today.** `reviewed_wtree` for review freshness, computed on committed trees (`verify.py:236-254`, `merge-serialization.md:20-22`). Adopted-current for that purpose.
**Adopting further.** Only needed for §4.1 (dirty-tree evidence). Port as-is.

### 4.3 `gstack-verify-gate` (Stop hook)
**What it does.** Reads `<!-- gstack:verify: cmd -->` from CLAUDE.md, runs it with `eval` only if `sha256(cmd)` is in a per-repo trust store; no CLAUDE.md / no declaration / untrusted command → allow (`:8-9`, `:161-167`); on failure exit 2 with the last 20 lines; re-entry blocks bounded at 3 per session, then allows with a warning (`:171-206`); trust grants are logged to a 0600 JSONL (`:96-113`).
**orca-fleet today.** `verify-gate.sh` is fail-closed on a named-but-missing manifest, on no manifest at `TaskCompleted`, on a missing contract source/digest, and on any verifier error (`:10-11`, `:66-80`, `:106-116`); it runs `verify.py`, not a user-declared command; signed dispatch record for off-worker soundness (`docs/verify-gate.md:120-168`).
**Adopting.** Nothing. The one transferable idea — the audit log of who granted trust — is already covered by the signed dispatch record. See §7.1 for the contradictions.

### 4.4 Egress receipts (`lib/egress-receipt.ts`, `gstack-egress-receipt`, `gstack-egress`)
**What it does.** Before any gstack-initiated off-machine send, append a content-free receipt `{id, ts, sink, host, payloadClass, bytes, sha256(payload), consent, prev=sha256(previous raw line)}` to `~/.gstack/security/egress.jsonl` (0600). Fail-closed sinks (brain-sync, memory-ingest, telemetry, tunnels, Memorable, impeccable download) refuse to send when the receipt cannot be written (`EGRESS_RECEIPT_FAILED`, exit 3); user-facing sinks warn and proceed (`lib/egress-receipt.ts:9-25`). `gstack-egress verify` recomputes the chain (exit 3 on tamper); `grants` lists every standing consent and its revoke command. A tripwire test sweeps the tree for unreceipted sinks (`CHANGELOG.md:1974-1975`). Explicit threat model: "forensic observability, not an exfiltration control".
**orca-fleet today.** No send-side record. The run-close integrity inventory hashes artifacts (`evidence-manifest.md:131-134`); `rw`/`danger` workers have unrestricted network (`sandbox-policy.md:23-31`); the danger lane's only egress discipline is "git push the work branch before teardown" (`:52-56`).
**Adopting.** Two layers. (a) Coordinator-side: a `runtime/scripts/egress.py write|verify` used before every off-repo write the fleet itself performs (PR open/comment, issue close, deploy trigger, `orca automations create`) — small, and it is the artifact `attest-it` needs for "what left the machine" (`docs/compliance-provenance.md` maps Art-12 logging). (b) Worker-side: per-worker egress cannot be receipted without a proxy; record it as a `sandbox-policy.md` requirement for the danger lane (the disposable sandbox's own network log is harvested with the branch) and leave `rw` as-is, stated. Effort: (a) ~half a day; (b) doc only.

### 4.5 `gstack-config`
**What it does.** Typed `~/.gstack/config.yaml` with a DEFAULTS table and validated keys (invalid values rejected, prior value kept — e.g. `memorable_recall`, `codex_reviews`, `cross_project_learnings`); `has` distinguishes "set" from "default".
**orca-fleet today.** Run configuration lives in the ledger header (`liveness-resume.md:78-90`: RUN, BASE, FORK_POINT, T0, SOURCE, WIP) and env opt-ins (`ORCA_COORD_ALLOW_AUTONOMOUS_WRITE`, `ORCA_COORD_ALLOW_DANGER`, `ORCA_COORD_ALLOW_CMD_OVERRIDE`). No per-user config.
**Adopting.** Not needed. If per-repo policy (WIP caps, NEVER_GATE lens list, reviewer vendor) ever moves out of prose, a validated `orca-fleet.toml` read by `preflight.py` would be the analogue; the validation rule "a typo must never flip a consent" is the part worth keeping.

### 4.6 Dispatch recovery (v1.79) + spawned-session contract (v1.76/1.78)
**What it does.** Every synchronous subagent dispatch in `/ship` carries `run_in_background: false`, pinned per generated file by a census test that also fails un-enumerated dispatch imperatives lacking the flag (`test/run-in-background-guidance.test.ts`; `scripts/resolvers/constants.ts:174`). Steps 7/8/10/18 have a ~10-minute deadline; on expiry the parent stops the task, and for doc-sync reconciles any commit the subagent made against the pre-dispatch HEAD (vets and pushes docs-only commits; never VERSION/package.json/CHANGELOG; a second failure branch covers a moved remote; stray staged edits surfaced, never discarded) and proceeds without the section; the dispatch contract has an explicit failure JSON so "could not run" is never read as "clean" (`CHANGELOG.md:227-229`, `:250`). Spawned subagents get `GSTACK_SESSION_KIND=spawned` on the command line; the preamble echoes it; only that echo arms auto-choose; destructive options are never auto-chosen; auto-chosen gates come back to the parent as a `decisions` array (`:402`, `:426-435`, `:299`).
**orca-fleet today.** Liveness: WATCH with `worker-list`/`worker-show`, 3 doctor attempts, reflection-before-retry, identical-error kill, `--retry-of` with fresh placement (`liveness-resume.md:17-59`). Nested depth rule (`dispatch-lifecycle.md:51-53`). Headless autonomy (`mission-scheduling.md:22-30`). Missing: (i) what happens to a killed worker's *worktree commits* — "respawn" today means a fresh placement, and the old worktree's partial commits are neither harvested nor declared discarded; (ii) a failure shape for a dispatched sub-step so the parent can distinguish "no findings" from "did not run"; (iii) auto-chosen decisions returned in `worker_done`.
**Adopting.** In `liveness-resume.md` WATCH: on kill/respawn, run a reconcile step — `git -C <old worktree> log <dispatch-time base>..HEAD` — and either harvest (cherry-pick into the retry's branch, recorded) or archive (branch kept, ledgered), never silently drop; record `dispatch_base_sha` on the ledger row at dispatch to make that computable. In `evidence-manifest.md` §1: `auto_decisions[]` (id, class, answer) on every worker manifest; a mutation unit with a one-way class in that array fails verification (the machine form of "one-way is never auto-resolved"). In `tests/test_architecture.py`: a census that every mission's dispatch preamble names `worker-start`/`--parent-worktree`/`PROFILE` — the same "enumerate every dispatch site and pin the load-bearing flag" pattern, applied to Orca flags instead of an Agent-tool flag. Effort: ~1 day.

### 4.7 Plan-completion audit classifier
**What it does.** A fresh-context subagent extracts every actionable item from the plan (checkboxes, numbered steps, file specs, test requirements, data-model changes; ignores Context/Questions/Deferred sections; cap 50), classifies **how** each can be verified — DIFF-VERIFIABLE (would appear in `git diff base...HEAD`), CROSS-REPO (sibling repo; verified by `[ -f path ]` if reachable), EXTERNAL-STATE (Supabase/DNS/Vercel env/OAuth allowlists — the diff cannot prove it), CONTENT-SHAPE (a file must follow a convention; run a detected validator) — then grades DONE / PARTIAL / NOT DONE / CHANGED / UNVERIFIABLE with a path-concreteness rule (a concrete path must be DONE or NOT DONE, never UNVERIFIABLE) and an honesty rule ("code that handles a deliverable is not the deliverable") (`plan-completion.md:70-106`). Gate: NOT DONE → stop / defer-to-P1 / drop; UNVERIFIABLE → **per-item** confirmation, blanket confirmation forbidden (VAS-449), user free-text evidence embedded in the PR (`:155-193`).
**orca-fleet today.** Criterion→test traceability verified on the integrated BASE head (`ship-it/SKILL.md:92-98`); two-level denominator (`evidence-manifest.md:65-80`); plan skeptic for orphan criteria / gold-plating (`decompose-dag.md:36-50`); `CODE_CLOSED` + `VERIFY_AT_SCALE` park for acceptance the fleet cannot prove (`ledger-contract.md:47-48`). No classification of a criterion's *verification mode*; an EXTERNAL-STATE criterion reaches the traceability table only as "no passing test" (UNMET) or as a worker-chosen park.
**Adopting.** Add `verification_mode ∈ {diff, external-state, cross-repo, content-shape}` to each frozen criterion at decide-and-freeze/decompose (the spec author classifies; the plan skeptic checks it). `verify.py`: `diff` criteria need a covering test + negative control; `external-state` criteria are **by construction** `CODE_CLOSED`+`VERIFY_AT_SCALE` with a named verify command and OPS ref (never a green); `cross-repo` criteria fail unless `mission-chaining.md`'s "no cross-repo chains" exception is recorded as a human decision; `content-shape` criteria require the validator command in `commands[]`. Keep gstack's per-item rule; do **not** keep its acceptance of a human's free-text "Y" as evidence (§7.4). Effort: ~1 day across `decide-and-freeze.md`, `decompose-dag.md`, `evidence-manifest.md`, `verify.py`.

### 4.8 Tracker trust envelope (`gstack-issue-guard`, `lib/tracker-guard.ts`)
**What it does.** The only sanctioned path for PR/issue text into context. Always envelopes (a clean scan is not proof of safety); detection-only NFKC + zero-width sweep labels injection-shaped lines through fullwidth/invisible evasion; forged envelope banners are defused; a fetch failure exits non-zero with **no** envelope ("empty is data, failed is not"); write-backs keep a separate raw artifact so envelope markup never reaches a live PR; a CI scanner fails the suite on any raw `gh issue/pr view` outside the guard at 8 ingress points (`CHANGELOG.md:1320`, `:1348-1350`).
**orca-fleet today.** Doctrine only: `sandbox-policy.md:84-92` ("quoted fenced with a marker and analyzed"), restated per mission (`clean-sweep:118-119`, `oss-contribute:124`, `review-it:67-69`, `harden-it:86-87`). No script fences anything; `spawn_worker.sh`/task specs embed enumerated text as the worker fetches it.
**Adopting.** `runtime/scripts/guard_text.py --source issue|pr|ci|web` (stdlib): banner + per-line `[INJECTION-PATTERN]` labels + NFKC/zero-width detection + non-zero-with-no-output on fetch failure; missions' enumeration commands (`clean-sweep source=tracker`, `oss-contribute` ENUMERATE, `review-it` PIN, dispatch-lifecycle bot ingest) route through it; a contract test greps `skills/` and `playbooks/` for raw `gh issue view`/`gh pr view --json body` and fails. Effort: ~1 day. This is the highest-leverage unadopted mechanism for the unattended sources (`mission-scheduling.md:22-30`).

### 4.9 Session-kind classification (`gstack-session-kind`)
**What it does.** Prints `spawned | headless | interactive` from env markers with a degrade-safe default (`interactive`); `GSTACK_SESSION_KIND=spawned` set by the dispatching skill outranks everything; only `spawned` is honored; the preamble echoes it as a STATUS line and *only that echo* arms auto-choose.
**orca-fleet today.** The rule is stated (`gate-classification.md:80-90`) but no component sets, records, or checks the kind. A coordinator decides "spawned → auto-pick" from its own memory of how it was launched.
**Adopting.** `spawn_worker.sh` exports `ORCA_SESSION_KIND=spawned` into every worker; `preflight.py` records the coordinator's kind (from `orca automations` context / a launch flag) into the ledger header as `KIND:`; `verify.py`/RESUME reject a `DECISIONS.md` line whose auto-resolve happened under `KIND: interactive` for a taste class that should have been asked. Effort: hours.

### 4.10 `gstack-diff-scope` (fail-loud scope detection)
**What it does.** Classifies the union of committed + working-tree + untracked changes into nine SCOPE_* flags; exits 2 with `SCOPE_ERROR=no_base` when the base is unresolvable (shallow CI checkout) and `SCOPE_ERROR=unmatched` when files changed but no category matched, printing the unmatched paths — "a green here would mean we could not look" (`:6-24`).
**orca-fleet today.** `risk-review.md:15-17` dispatch rule is prose; a shallow clone or a novel layout silently dispatches no lens, and the DECISIONS tally then records a legitimate-looking zero.
**Adopting.** `runtime/scripts/diff_scope.py` with the same exit contract; `risk-review.md` dispatch reads its flags; `SCOPE_ERROR` is a finding (park the review, never a silent gate-off). Effort: hours. High value for `review-it` scheduled sweeps.

### 4.11 PreToolUse deny hooks (`careful`, `freeze`, `guard`)
**What it does.** `careful`: PreToolUse on Bash returns `hookSpecificOutput.permissionDecision:"ask"` on destructive patterns and `"deny"` on the HIGH tier (recursive delete of `/`, `~`, `$HOME` incl. `--no-preserve-root`; force-push to the default branch incl. `+main` refspecs; simple commands only; `--force-with-lease` never matches); additive-only project patterns (`careful/SKILL.md:43-79`). `freeze`: PreToolUse on Edit/Write denies paths outside one directory, fail-closed on unparseable payloads, symlinks resolved, EXIT backstop denies on unexpected death (`CHANGELOG.md:1322`, `:207`). Effort: ~1 day. Note the boundary: it is defense-in-depth inside the worker's session (the same advisory status as the native verify gate, `docs/verify-gate.md:98-101`), not a soundness boundary.

### 4.12 One-way-door registry + preference hook
**What it does.** `scripts/question-registry.ts` gives every recurring question a stable id, a category, and `door_type` (one-way | two-way); one-way doors are "ALWAYS asked regardless of user preference"; the PreToolUse `question-preference-hook` enforces never-ask/always-ask deterministically ("no agent compliance required") and denies with the recommended option in the reason for two-way questions; a keyword net (`gstack-question-preference --check --summary-stdin`) catches unregistered destructive phrasings ("rotate the credentials") so a stored never-ask can never auto-decide one (`CHANGELOG.md:2108`).
**orca-fleet today.** Mechanical/taste/one-way is classified per decision in prose (`gate-classification.md:30-36`); the one-way list is a sentence (`:36`).
**Adopting.** `runtime/one-way-doors.json` (the sentence, as data: merge-to-default, deploy, rollback, deletion, spend, scope change, secret rotation, live credentials, freeze) + a keyword net; `verify.py`/RESUME fail a DECISIONS line whose `class` is not `one-way` but whose text matches the net, or whose `class=one-way` lacks a human `source`. Effort: hours; closes the "agent mis-classifies its own gate" hole.

## 5. New mission candidates

Each candidate is run through the five-point test against the nearest existing mission. Names are outcome names.

### 5.1 `absorb-it` — every inbound contribution is landed with authorship, refuted with receipts, or parked with a named ask

- **Outcome.** A maintainer's open inbound-PR queue is drained: each PR is absorbed (cherry-picked with authorship preserved, amended where review finds a gap, regression test proven RED on the pre-absorption base), superseded-by-main (closed with the commit that fixed it), duplicate (closed pointing at the winner), or parked awaiting the contributor.
- **Why gstack makes it visible.** It is the release process gstack runs every week: "18 community PRs absorbed with authorship preserved, twelve with wave amendments" (`CHANGELOG.md:275`), "90 stale PRs and 21 issues closed with receipts" (`:896-898`), "~50 community PRs absorbed" (`:1756`), "every behavior fix carries a regression test proven red on a v1.77.0.0 scratch worktree via base-compatible reproducers — tests that merely fail to compile on the base don't count as receipts" (`:335`). No gstack skill does it; the maintainer does it by hand each wave.
- **Unit of work.** One inbound PR (its diff + its linked issue), not a finding.
- **State machine.** ENUMERATE (open PRs, paginated; linked issues) → CLASSIFY {absorbable · superseded-by-main · duplicate-of · needs-contributor · out-of-scope} with a reproduction of the claimed defect on current main → ABSORB (cherry-pick/apply preserving `Author:`; wave amendment as a separate commit by the fleet; DCO/CLA state checked) → RECEIPT (the PR's regression test, or one the fleet writes, run on a scratch worktree of the pre-absorption base → RED; on the absorbed head → GREEN) → build-blind REVIEW → LAND (merge train, one PR per absorbed contribution against BASE) → CLOSE (the inbound PR closed with the landing SHA and the credit line; linked issues closed with the same receipt) → re-ENUMERATE until dry.
- **Convergence proof.** Full re-enumeration of the inbound queue finds zero PRs not in a terminal class; every absorbed PR has: preserved authorship on the landed commit (`git log --format=%an` asserted), a receipt (test RED on base / GREEN on head, both pasted with SHAs), a merged SHA on BASE, and the inbound PR closed with a comment linking both. Superseded closes quote the main commit that made the PR moot. Denominator frozen per loop at `T0` like `clean-sweep source=tracker`.
- **Ordering / isolation.** Overlapping inbound PRs (same files, same bug fixed twice — gstack's tracker shows "several contributors independently fixed the same bug within days", `:1769-1770`) form an absorption chain: the first lands, the rest are re-classified against the new main, never merged blind. Hot-file chains as in `merge-serialization.md`.
- **Parking.** `needs-contributor` (CLA/DCO unsigned, question unanswered — a comment posted, 1 follow-up round, then park), `design-disagreement` (maintainer one-way), `cannot-reproduce-claimed-defect` (the PR's premise is refuted with attempts logged → close as refuted only after the batch gate).
- **Terminal states.** `ABSORBED` / `ABSORBED-WITH-PARKED`.
- **Not one of the 17.** Nearest is `clean-sweep` (unit = a finding you fix from scratch, `remediate-finding.md:9-13`) and `oss-contribute` (you are the outsider, no merge rights, `upstream-contribution.md:9-15`). `absorb-it` differs on unit (someone else's diff), state machine (absorb + amend + credit, not build), convergence proof (queue dry *and* authorship + receipt per landing — a clean-sweep close has no authorship invariant), ordering (overlap chains between inbound diffs), and parking (`needs-contributor`, a class no existing mission has). Three of five differ; it is not a source of `clean-sweep`.
- **Worker recipe.** matt `code-review` + gstack review army for the build-blind review of an absorbed diff; gstack `ship` Step 15.1 (bisectable, author preserved) for landing; `upstream-contribution.md` etiquette inverted (maintainer-side reply templates).
- **Reasons to reject.** (1) Many maintainers want to absorb by hand; the value is highest for high-volume repos only. (2) Authorship preservation conflicts with orca-fleet's commit hygiene "author = the maintainer" (`dispatch-lifecycle.md:105`) — the mission would need an explicit carve-out, and squash-vs-merge policy per repo. (3) It could be argued as `clean-sweep source=inbound-prs` if one accepts "absorb" as a fix strategy; the counter-argument is the receipt shape and the parking class, but reasonable people could put it in clean-sweep.

### 5.2 `drive-it` — every frozen user journey drives green in a real browser at the head SHA

- **Outcome.** A running web surface's frozen journey set (pages × flows) is driven end-to-end through a real browser at the BASE head; defects found are fixed, re-driven green, and revert-controlled; the health score never regresses against the pre-run baseline.
- **Why gstack makes it visible.** `/qa`, `/qa-only`, `/browse`, `/canary`, `/benchmark`, `/devex-review` all ride one browser-driving contract; the README calls `/qa` "a massive unlock … from 6 to 12 parallel workers" (`README.md:338`). orca-fleet has no mission whose oracle is a driven browser session; `access-it` uses axe over a rendered page (no journeys), `speed-it` measures, `field-test-it` drives a device.
- **Unit of work.** One journey defect on the frozen surface (or one journey pass in report-only mode).
- **State machine.** FREEZE the journey set (URL list × named flows × auth state; digest-locked) → BASELINE (each journey driven at the BASE head: console errors, screenshot, DOM diff, link status, per `qa-only` Phases 1–6; health score recorded) → ENUMERATE defects (severity Critical/High/Medium/Low per `qa-only:855-866`) → FIX (rw workers, `remediate-finding`, one defect per unit; regression test per fix as `qa:805`) → build-blind REVIEW → LAND → RE-DRIVE the affected journeys at the unit's head SHA (GREEN) with the negative control (revert the fix → the driven journey reproduces the defect artifact) → FINAL DRIVE of the whole frozen set → VERDICT.
- **Convergence proof.** Every journey in the frozen set has a GREEN drive artifact at the final BASE head (screenshot + console + evidence lines with the head SHA in the artifact name); every defect is fixed-with-revert-control or PARKED; final health score ≥ baseline (a lower score is a regression finding, `qa:879-885`); the verifier replays a ≥10% sample of drives from the archived scripts at the merged SHA.
- **Ordering / isolation.** Journeys parallelize across browser lanes (one profile/cookie jar per lane; shared-state journeys — cart, account — serialized); fixes follow hot-file chains.
- **Parking.** `needs-human-session` (sign-in wall, CAPTCHA, MFA — the human completes it in their own browser per gstack's "credentials never pass through the agent", `qa:560`), `third-party-widget` (not fixable from source, `qa:716`), `mutating-action-on-non-local` (a journey step that would mutate a non-local target is a one-way human grant per gstack rule 3 and `gate-classification.md`).
- **Terminal states.** `DRIVEN` / `DRIVEN-WITH-PARKED`; report-only mode (`review-it` analogue): `HEALTHY` / `DEGRADED` verdict bound to head SHA.
- **Not one of the 17.** vs `field-test-it`: same state-machine shape (baseline → reproduce → fix → re-verify) but different unit (a journey on a frozen surface vs a device-observed defect), different convergence proof (frozen journey set all green + score non-regression vs defect set closed), different ordering (parallel browser lanes vs one serial lane per physical device, `field-test-it:96-97`), different parking (auth/CAPTCHA/third-party vs device/OS/pairing). vs `access-it`: same "frozen surface" denominator idea, but the oracle is behaviour under interaction, not a static rule set. vs `speed-it`: measurement vs function.
- **Worker recipe.** gstack `qa` / `qa-only` methodology + the Aside/`$B` driver contract (§6.3) for the drive workers; matt `tdd` or addy build for the fix workers.
- **Reasons to reject.** (1) This is the strongest case for extending `field-test-it` with an oracle tier `BROWSER` beside `EMULATOR`/`PHYSICAL` (`field-test-it:57-60` already types the oracle) — two of the five points are shared, and the differences could be written as tier rules. (2) A browser substrate (Aside is macOS-only; the bundled Chromium is gstack's) is a dependency orca-fleet does not carry; Orca ships a browser but no version-matched driver contract was witnessed here. (3) The health score is a taste instrument; without it the "non-regression" clause reduces to "no new defects", which is the defect-set proof `field-test-it` already has.

### 5.3 `document-it` — every public surface entity is documented in the quadrants it needs, and every claim is true

- **Outcome.** The public surface (commands, flags, config keys, endpoints, exported modules, skills) has a Diataxis coverage map with zero critical gaps; generated/updated docs' claims are verified against the tree; architecture diagrams reference only entities that exist.
- **Why gstack makes it visible.** `/document-release` builds the coverage map but "informs, never generates" (`document-release/SKILL.md:600-602`); `/document-generate` fills gaps in a strict order (reference → explanation → how-to → tutorial, `:560-700`); the README calls doc drift "the engineer you never had" (`README.md:344`). orca-fleet's `release.md:28-31` syncs docs to a wave and `clean-sweep source=doc-claims` removes false claims, but "Generating NEW docs is not this mission" (`clean-sweep:246-247`) and nothing owns *missing* docs.
- **Unit of work.** One (public-surface entity × quadrant) cell of the coverage map.
- **State machine.** EXTRACT the public surface at the BASE head (exports, CLI flags, config keys, endpoints, skills — a script, not a reading) → MAP coverage per quadrant by grep-able evidence (a doc mentions the entity in a reference table / a how-to step / a tutorial / an explanation) → FREEZE the gap list (critical = zero coverage; the human bounds which entities merit tutorial/explanation — taste gate) → WRITE (rw workers, one cell per unit; reference first, from code archaeology, `document-generate:489-560`) → CLAIM-VERIFY (every factual claim in the new doc bound to a `file:symbol` or a run — the doc-claims oracle from `clean-sweep`) → build-blind REVIEW (voice, discoverability: reachable from README) → LAND → RE-MAP → VERDICT.
- **Convergence proof.** The coverage map re-derived at the final head shows zero critical gaps and every frozen cell filled; every claim in a landed doc has a verified anchor (the negative control: mutate the anchored fact — rename the flag — and the claim-check goes RED); diagram entities cross-reference clean; every doc is reachable from README/AGENTS.md. Denominator = the frozen surface × quadrant cells; new surface joins the next loop.
- **Ordering / isolation.** Reference cells before how-to/tutorial cells for the same entity (`document-generate:560`); docs touching the same file form a chain.
- **Parking.** `explanation-needs-author` (the "why" behind a design is not in the tree — human owner named), `tutorial-not-warranted` (human-declined cell), `diagram-needs-human` (advisory, `document-release:604`).
- **Terminal states.** `DOCUMENTED` / `DOCUMENTED-WITH-PARKED`.
- **Not one of the 17.** vs `clean-sweep source=doc-claims`: unit differs (a coverage cell vs a false claim), convergence differs (map shows zero gaps vs re-enumeration finds zero false claims), parking differs (author-knowledge parks). vs `ship-it`: a doc slice inside ship-it covers the wave's diff only (`release.md:28-31`), not the standing surface.
- **Worker recipe.** gstack `document-generate` (Diataxis partition + templates) and `document-release` (coverage map, diagram drift, CHANGELOG/VERSION rules) for writers; the `clean-sweep` doc-claims verifier for CLAIM-VERIFY.
- **Reasons to reject.** (1) "Documented" quality is taste; the machine-checkable part (coverage cell filled, claims anchored, discoverable) may be thin enough that this is a `floor-it` dimension ("doc coverage ≥ X% of public surface") plus a `clean-sweep` source, not a mission. (2) Tutorials/explanations written by an agent are exactly the "LLM-written context hurts" class compound-learn cites (`compound-learn.md:3-5`) — the mission would ship prose humans must read to trust. (3) Public-surface extraction differs per language; the script is the hard part.

### 5.4 `onboard-it` — a stranger reaches hello-world on a clean machine inside the budget, every documented step executed

- **Outcome.** The documented getting-started path executes green on a clean environment within a pre-declared TTHW budget; every step, error message, and upgrade path is verified by execution, not by reading; regressions are fixed and re-executed.
- **Why gstack makes it visible.** `/devex-review` "actually tests your onboarding: navigates docs, tries the getting started flow, times TTHW, screenshots errors" with a per-row method label TESTED/PARTIAL/INFERRED (`devex-review:861-880`) and compares plan scores with live scores ("boomerang", `:883`); `/plan-devex-review` sets the plan. gstack's own v1.80 release was driven by fresh-machine install failures ("a laptop on hotel wifi, a CI runner behind a proxy, or a fresh Ubuntu 24.04 box", `CHANGELOG.md:199`).
- **Unit of work.** One documented onboarding step (install / configure / first command / first success) on one declared persona-environment (OS × package manager × auth state).
- **State machine.** FREEZE (the getting-started path as written; the persona-environment matrix; TTHW budget per persona — one-way freeze) → BOOTSTRAP a disposable environment per persona (`sandbox-policy` danger/sandbox lane; no cached state) → EXECUTE each step verbatim from the doc, timing it, capturing stdout/stderr/screens → CLASSIFY each step PASS / FAIL(doc) / FAIL(product) / NEEDS-CREDENTIAL → FIX (doc fix or product fix, `remediate-finding`) → build-blind REVIEW → LAND → RE-EXECUTE the step and its successors on a fresh environment at the head SHA; negative control: revert the fix → the step fails again in a fresh environment → VERDICT.
- **Convergence proof.** Every step in the frozen path is PASS on every frozen persona-environment at the final head, with the measured TTHW ≤ budget (median of ≥3 fresh runs, `speed-it`'s contract shape), or PARKED with the credential/account it needs; each fix has a revert-RED on a fresh environment. The path was executed, never inferred (a row whose method is INFERRED is not done).
- **Ordering / isolation.** Steps are sequential within a persona; personas parallelize (one sandbox each); a doc fix and a product fix to the same step serialize.
- **Parking.** `needs-credential` (an account, a paid key — human-provisioned, Lane 0), `platform-unavailable` (no macOS runner), `budget-decision` (TTHW over budget with no product change in scope — one-way).
- **Terminal states.** `ONBOARDED` / `ONBOARDED-WITH-PARKED`.
- **Not one of the 17.** vs `speed-it`: TTHW is a metric but the unit is a documented step and the oracle is fresh-environment execution, not a journey measurement. vs `document-it`: document-it proves docs *exist and are true*; onboard-it proves the path *works when followed* — a true doc can still fail on a proxy. vs `drive-it`: the oracle is a shell on a clean machine, not a browser. vs `floor-it`: a TTHW budget could be one floor dimension, but floor-it installs gates; it does not execute a path across personas.
- **Worker recipe.** gstack `devex-review` (eight audits, scorecard with method labels, TTHW benchmarks) for the executor; addy `incremental-implementation` for fixes.
- **Reasons to reject.** (1) A disposable environment per persona is expensive and most repos have one persona. (2) The "stranger" is an agent; agents tolerate errors humans would not and vice-versa — the evidence is weaker than it looks. (3) It may be adequately served by `field-test-it` with an `ENVIRONMENT` oracle tier, the same objection as 5.2.

## 7. Risks — where gstack's design contradicts orca-fleet's doctrine; what not to copy

### 7.1 Fail-open gates
- `gstack-verify-gate` "Fails open on every absence (no CLAUDE.md, no declaration, empty value)" (`:8-9`); "Untrusted commands never block the turn" (`:17`); after three blocked re-entries it **allows** with a warning ("Verification is RED; do not treat this turn as verified", `:200-206`) — the exact pattern `floor-it/SKILL.md:113-115` names as a vacuous gate. orca-fleet: `verify-gate.sh:10-11`, `:106-116` block on absence and on verifier error. Do not copy.
- `gstack-evidence check` is "advisory — a failed CHECK never blocks" (`ship/SKILL.md:947`, `readiness-gate.md:122`); `--allow-paths package.json` accepts a behaviour-changing edit in the bump window as a documented residual risk (`ship:930-936`). If §4.1 is adopted, the check must fail the unit.
- Egress receipts are fail-closed only for "sensitive" sinks and fail-open with a warning for "user-facing" ones (`lib/egress-receipt.ts:9-13`). A fleet's sinks are all unattended; choose fail-closed uniformly.
- `gstack-evidence` dotenv scrub "fails open" on an unreadable `.env` and leaves bun-expanded `${VAR}` values in place (`CHANGELOG.md:756`).
- gstack's own history is the argument: `/freeze` and `/careful` emitted a payload the host ignored for months — "deny meant allow" (`CHANGELOG.md:1763-1764`) — and `/freeze` allowed every edit under `GSTACK_HOME` until v1.80 (`:184`). Any deny hook orca-fleet adds (§4.11) ships with a test that proves it denies.

### 7.2 Same-session verification
Every `/ship` gate — plan-completion audit, coverage audit, review army, adversarial review, evidence check, doc-sync — runs inside the producing session or in a subagent it spawned with its own environment inherited byte-for-byte (`bin/gstack-session-kind:22-23`). The "fresh context" of a subagent is not an independent verifier: it shares the worker's checkout, env, and credentials, and the parent parses its final line as JSON. orca-fleet's oracle is a different process re-deriving against authorities outside the manifest (`evidence-manifest.md:107-110`; `docs/verify-gate.md:83-89`). `REVIEW.md:268-274` already records this. Do not import any gstack gate as a completion oracle; import them as worker-side discipline only.

### 7.3 The reviewer mutates the code
`/review` Fix-First auto-applies AUTO-FIX findings ("dead code, N+1, stale comments, magic numbers, missing LLM output validation, version/path mismatches…", `review/checklist.md:146-172`, `review/SKILL.md:818-821`), and `/ship` Step 9 runs the same flow before commit. This collapses builder and reviewer into one session and lets a review change the reviewed tree. orca-fleet: `review-it` has no fix authority (`:21-23`), the reviewer is build-blind (`acceptance-review.md:4`), and a post-review push voids the review (`reviewed-sha-freshness.md:8-10`). Do not copy Fix-First into any review playbook; route AUTO-FIX-class findings to the builder as a batched change request (`dispatch-lifecycle.md:92-97` already does this for bots).

### 7.4 Human free-text accepted as verification
Plan-completion's UNVERIFIABLE gate accepts "Y) Confirmed done — cite what you verified (free-text, embedded in PR body)" (`plan-completion.md:176-185`). Per-item confirmation is right; a sentence is not an artifact. orca-fleet's equivalent is `CODE_CLOSED` + a written verify command and OPS ref (`ledger-contract.md:53-55`). Adopt the classifier (§4.7), not the acceptance rule.

### 7.5 Scope expansion by principle
Autoplan principle 2 auto-approves expansions "in blast radius AND < 1 day CC effort (< 5 files, no new infra)" and principle 6 is "Bias toward action — merge > review cycles > stale deliberation" (`autoplan/SKILL.md:570-580`); the ethos is "Boil the Ocean" (`ETHOS.md`, every tier-2+ preamble). orca-fleet freezes the denominator and treats mid-run growth as scope creep (`reshape-it:111-112`, `build-change.md:20-21` NOTICED-BUT-NOT-TOUCHED, `evidence-manifest.md:65-80`). The compatible part is gstack's own carve-out — "User Challenges … NEVER auto-decided … destructive options never auto-chosen" (`autoplan:600-611`, `CHANGELOG.md:402`) — which orca-fleet already has. Do not import the principles.

### 7.6 Scores as verdicts
`quality_score = max(0, 10 − 2·critical − 0.5·informational)`, and `10.0` when specialists were skipped on a small diff (`review/SKILL.md:938`); `/health` redistributes the weight of a missing tool so the composite is unaffected by what could not be measured (`health/SKILL.md:536`); a ship is CLEARED by "≥1 eng review entry within 7 days with status clean" (`ship/SKILL.md:620-621`). All three make a number look complete when part of the check did not run — the class `floor-it` forbids. orca-fleet's terminals are booleans over evidence (`ledger-contract.md:16-40`). Do not adopt composite scores as gates; a measurement without a frozen contract is `unmeasured` (`speed-it:41-42`).

### 7.7 Review-freshness fallback weaker than orca-fleet's
"0 commits since review → CURRENT … 4+ commits → STALE" (`readiness-gate.md:39-41`) grades a review current after up to three unreviewed commits when no wtree is on record. orca-fleet voids on any content change (`reviewed-sha-freshness.md:8-14`). Keep the stricter rule; the content-identical equivalence class is already adopted.

### 7.8 Autonomous merge of the promotion
`/land-and-deploy` merges the PR without asking ("The user said `/land-and-deploy` which means DO IT", `:591-594`; only first-run, CI, conflicts, and deploy failure stop it). orca-fleet: BASE→default promotion is a one-way human gate; the fleet opens the PR and stops (`README.md:469-474`, `gate-classification.md:36`). Do not copy. The revert-at-every-failure discipline (`:923-941`) and staging-first offer (`merge-and-deploy.md:231-252`) are already in `release.md:44-46` and compatible.

### 7.9 Commit hygiene
`/ship` adds a `Co-Authored-By` trailer to the final commit (`ship/SKILL.md:910`) and continuous-checkpoint mode auto-commits `WIP:` commits with a `[gstack-context]` body (`:297-320`), squashed later. orca-fleet: author = the maintainer, no trailers, bisectable, no WIP (`dispatch-lifecycle.md:104-108`, `build-change.md:22-24`). Do not copy either. `absorb-it` (5.1) would need an explicit authorship carve-out.

### 7.10 Learnings applied automatically
"Prior learning applied: [key] (confidence N/10)" is injected into reviews and ship (`plan-completion.md:292-298`); learnings are written by the agent with self-assigned confidence and decay. orca-fleet's `compound-learn.md:3-5`, `:40-41` (ETH Zurich finding; human approves each line) stands. Keep excluded.

### 7.11 Host-specific recovery imported as doctrine
v1.79's recovery is built around Claude Code's Agent tool backgrounding subagents (`run_in_background: false`). orca-fleet dispatches through Orca `worker-start`; the flag is meaningless there. Import the *shape* (deadline → stop → reconcile orphaned commits → explicit failure record → proceed) and the *census test*, not the flag (§4.6).

### 7.12 Instruction surface
Every tier-2+ gstack skill is 900–1,900 generated lines with ~430 lines of shared preamble (`qa/SKILL.md:1-431`); v1.71 halved the eager bill and still lands at 53.7 KB per `/review` invocation (`CHANGELOG.md:632`). orca-fleet caps missions at 130 lines / 31,200 bytes (`scripts/validate.py:96-104`). Any playbook in §6 must be written from the mechanism, not transcribed; a transcribed gstack section would blow the 90-line cap several times over.
