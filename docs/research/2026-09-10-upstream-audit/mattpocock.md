## 5. New mission candidates

Each is tested against the five points (unit · state machine · convergence proof · ordering/isolation · parking) versus all 17 existing missions.

### C1. `name-it` — one name per concept, and the code agrees

- **Outcome:** the repo's domain vocabulary is a single glossary that code identifiers, docs, and tracker language all conform to, with every hard-to-reverse choice behind it recorded.
- **Unit of work:** one domain term (a concept and its canonical name; its synonyms are the term's `_Avoid_` set).
- **State machine:** HARVEST (candidate terms from identifiers, docs, issue titles, commit messages; cluster synonyms; detect overloads — one word, N meanings) → FREEZE-SET (human bounds the term list; headless parks here) → DECIDE per term (HITL: canonical name, definition, avoid-list; ADR only if hard-to-reverse ∧ surprising ∧ real trade-off — `domain-modeling/SKILL.md:66-74`) → RECORD (`CONTEXT.md` entry in `CONTEXT-FORMAT.md` shape; ADR file) → RECONCILE (code/doc uses of a banned synonym: rename as a *wide refactor* per `decompose-dag.md:12-13`, or an explicit "legacy identifier, not renamed" exception) → GUARD (a vocabulary check — grep/lint for avoid-list tokens in new diffs — proven RED on an injected synonym, floor-it style) → RE-HARVEST.
- **Convergence proof:** every frozen term has a glossary entry; a full re-harvest finds zero unresolved overloads and zero banned-synonym uses outside recorded exceptions; the guard's injected-violation transcript is RED-then-GREEN at `head_sha`. Negative control per rename unit: revert the rename → the guard goes RED again. Terminals **NAMED** / **NAMED-WITH-PARKED** (a term whose rename is an API break parks at the one-way gate).
- **Ordering/isolation:** DECIDE strictly before RECONCILE; renames touching shared symbols form a merge chain (`merge-serialization.md:31-32`); glossary writes are a hot file.
- **Parking:** `needs-human` (the meaning is contested), API-break one-way, `legacy-exception` (recorded, counted clean).
- **Why not one of the 17:** clean-sweep's unit is a finding closed by a merged SHA + a failing-first test; here the unit is a *term*, the oracle is a vocabulary-consistency check, and the decision step is HITL per unit. reshape-it changes interface *shape*, not names. floor-it could host the GUARD as a dimension but has no DECIDE/RECORD phases. Distinct on unit, state machine, and proof.
- **Worker loads:** `domain-modeling` (+ `CONTEXT-FORMAT.md`, `ADR-FORMAT.md`), `to-tickets` wide-refactor rules for the rename batches, `code-review` Standards axis ("Mysterious Name").
- **Honest reasons to reject:** the payoff upstream claims is conversational concision (`README.md` "#2"), which a fleet does not feel; renames are churn with real regression risk for a cosmetic oracle; the DECIDE phase is nearly all HITL (L2–L3), so a fleet adds little over a single grilling session; a vocabulary lint may be enough as a floor-it dimension.

### C2. `orient-it` — a stranger can find their way

- **Outcome:** the repo's agent-facing context (AGENTS.md/CLAUDE.md, pointed-at docs, glossary) is proven sufficient: a fresh session completes a frozen set of representative tasks without an unanswerable question, and carries no instruction that changes nothing.
- **Unit of work:** one navigation gap — a fact a cold session could not find (a convention, a command, a gotcha), or one steering line under a no-op test.
- **State machine:** PROBE (dispatch fresh `ro` sessions on a frozen probe suite: "find where X is configured", "run the tests for Y"; record asks, wrong turns, time-to-find) → GAP (each failure classified: missing pointer / stale cache / no-op line / missing information access — the `retro` categories) → DECIDE (cache it or leave it to the environment, `writing-for-agents:79`; human approves every AGENTS.md line per `compound-learn.md:37-41`) → WRITE (pointer or doc, one unit) → RE-PROBE (fresh session; gap closed) → PRUNE (remove lines the no-op test shows change nothing) → REFLECT.
- **Convergence proof:** the frozen probe suite passes with zero unanswerable asks across N fresh sessions (a small streak, deflake-style, because the oracle is behavioural); every kept steering line has a probe that fails without it (negative control: delete the pointer → the probe fails); every removed line has a probe that passes without it. Terminals **ORIENTED** / **ORIENTED-WITH-PARKED**.
- **Ordering/isolation:** PROBE sessions are strictly cold (fresh worktree, no ledger, no prior transcript); WRITE units are `lit` and human-approved.
- **Parking:** `needs-human` (a convention nobody can state), `information-access` (needs a credential or log tee the fleet cannot provision — hands to C3).
- **Why not one of the 17:** compound-learn is a per-run *proposal* with no denominator and no re-probe; clean-sweep `source=doc-claims` closes *false* claims, not *missing* pointers, and has no behavioural oracle; floor-it enforces numeric thresholds. Distinct on unit (a gap), proof (cold-session probe streak), and negative control (delete-the-pointer).
- **Worker loads:** `writing-for-agents` (+ `SKILL-MECHANICS.md`), `retro`, `domain-modeling` read-only, `teach` only for the human-facing onboarding variant.
- **Honest reasons to reject:** the oracle is an LLM run — noisy, model-dependent, and not "unfakeable" in the `gate-classification.md:50-51` sense, so units can never be `dark-eligible`; the ETH finding compound-learn cites ("LLM-written AGENTS.md hurts") argues that the WRITE phase is where damage is done; probe suites drift as the repo changes, so the denominator needs its own maintenance; the same value may be reachable by extending compound-learn with a re-probe step.

### C3. `unblock-it` — the human-owed queue, packaged and verified

- **Outcome:** every item a fleet parked on a human (credentials, dashboard configuration, a signature, a decision only one person can make) is delivered as an executable procedure or a targeted questionnaire, and its completion is *verified* before the originating mission unparks.
- **Unit of work:** one human-owed item (a ledger `park` line of class `needs-human`, a `VERIFY_AT_SCALE` OPS item, a `MAPPED-WITH-BLOCKED` ticket, an attest-it GAP).
- **State machine:** ENUMERATE (the frozen human-owed queue across ledgers/OPS notes; digest) → CLASSIFY (procedure → wizard; knowledge → questionnaire; approval → a one-line brief with the recorded gate id — `loop-me`'s **brief** rule) → PACKAGE (author the artifact; static-trace it per `wizard/SKILL.md:41-43`; every captured value maps to where it is consumed) → HAND (deliver; record recipient + timestamp) → VERIFY-COMPLETE (the produced state observed by the fleet: secret present in CI, rotated key refused by the API, questionnaire file answered with no stub left, gate resolved) → UNPARK (write the originating ledger row's park to empty; the originating mission re-enters at its own state machine).
- **Convergence proof:** every item in the frozen queue is VERIFIED-COMPLETE with an observation artifact or still OWED with its packaged artifact path and recipient; negative control: revoke/blank the produced value → the verify probe goes RED. Terminals **UNBLOCKED** / **UNBLOCKED-WITH-OWED**.
- **Ordering/isolation:** items are independent; wizards never run by the fleet (`wizard:43` "Don't run it end-to-end yourself"); secrets never enter the ledger (`diagnose.md:5-14`).
- **Parking:** `owed` (the human has not acted) is the normal terminal, a handoff not a degradation (`mission-chaining.md:22-24` pattern).
- **Why not one of the 17:** no mission owns the queue; each *produces* parks and stops. mission-chaining carries parks forward as enumeration input but never resolves them. Distinct on unit (a human-owed item), oracle (an observation of the produced state), and terminal (owed is clean).
- **Worker loads:** `wizard` (+ `template.sh`), `to-questionnaire`, `wayfinder` Task-ticket rules, `handoff` for the brief.
- **Honest reasons to reject:** it is mostly an artifact generator; the "verification" half is small and item-specific; it could be a playbook every PARK composes (§6 P2) rather than a mission with its own coordinator; scheduling it unattended is pointless (its whole value lands after a human acts).

### C4. `automate-it` — a recurring loop specified, installed, and observed firing

- **Outcome:** each recurring workflow the human wants delegated has a spec an implementer could build without a question, is installed as an unattended automation, and has been observed producing its brief on a real trigger.
- **Unit of work:** one loop (a trigger + a workflow spec).
- **State machine:** FIND (the loop lens: enumerate candidate loops from the repo's calendar of pain — CI retries, nightly checks, release chores, inbox triage) → GRILL (round-by-round, output = a `workflows/<name>.md` spec with trigger / checkpoint / push-right / brief) → FREEZE (human confirms the loop set and each checkpoint — a checkpoint is a gate classification, `gate-classification.md:30-36`) → INSTALL (`orca automations create`, `mission-scheduling.md:8-14`, or a CI schedule) → FIRST-FIRE (observe one real trigger; the brief lands; every one-way gate parked, never faked) → GUARD (the automation's existence and schedule are re-witnessed, pin-it style) → REFLECT.
- **Convergence proof:** every frozen loop has a spec meeting the "no question left" DoD (`loop-me:27`), an installed automation id, and a first-fire artifact; negative control: disable the automation → no brief at the next trigger. Terminals **AUTOMATED** / **AUTOMATED-WITH-PARKED**.
- **Ordering/isolation:** INSTALL after FREEZE only; one automation per loop; an automation that itself runs a mission inherits `mission-scheduling.md`'s "value lands before a one-way gate" test.
- **Parking:** `needs-human` (a checkpoint cannot be pushed right of a one-way door), `no-trigger` (the event is not observable).
- **Why not one of the 17:** mission-scheduling is a *runtime policy* about running missions on a cadence; it has no unit, no spec artifact, no first-fire proof. ship-it builds a change, not a schedule. Distinct on unit and proof.
- **Worker loads:** `loop-me`, `grilling`, `wizard` for checkpoints that need a human, `writing-for-agents` for the spec.
- **Honest reasons to reject:** most loops worth automating are *missions* already (nightly clean-sweep, weekday review-it), so the mission collapses into "write the `orca automations create` line"; loop-me is in-progress and personal-productivity-shaped; the first-fire oracle for an event-triggered loop may take days.

### C5. `record-it` — decisions the code still honours (weak candidate)

- **Outcome:** every hard-to-reverse, surprising, trade-off decision visible in the code has an ADR, and every existing ADR is current, superseded, or flagged as contradicted by the code.
- **Unit:** one decision. **State machine:** DETECT (deviations from the obvious path, lock-in choices, constraints not visible in code — `ADR-FORMAT.md:39-47`) → TRIPLE-TEST → INTERVIEW (HITL: the why) → RECORD → VERIFY-HONOURED (grep/probe that the code matches the ADR) → RE-DETECT. **Proof:** every candidate has an ADR or a recorded "not an ADR" verdict; every ADR has a CURRENT/SUPERSEDED/CONTRADICTED disposition with evidence. Terminals **RECORDED** / **RECORDED-WITH-PARKED**.
- **Why not existing:** pin-it re-witnesses *runtime* doctrine against a binary; this re-witnesses the *repo's own* decisions against its code; clean-sweep doc-claims needs a falsifiable claim to exist first.
- **Reject because:** the "why" lives only in human memory, so the mission is an interview with a file writer attached (L2); DETECT has no oracle (what counts as "surprising" is taste); better folded into C1's RECORD phase or into decide-and-freeze's ADR rule.
